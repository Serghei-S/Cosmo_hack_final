# Контракты ОРБИТА.QC

Пять JSON Schema Draft 2020-12 описывают закрытые конверты сообщений и версионированные границы системы:

- `production-event.schema.json` — единое производственное событие;
- `delivery.schema.json` — доставка события и необязательная серверная квитанция;
- `quality-decision.schema.json` — отдельное решение контролёра;
- `integration-exchange.schema.json` — задания и результаты ERP, пакет и квитанция MES;
- `mobileops.schema.json` — задание, результат и управление учебным каналом MobileOps.

Проверка запускается из `source`:

```powershell
pnpm contracts:check
```

Команда проверяет ссылки между схемами, весь встроенный поток, ERP-фикстуры и отрицательные примеры. Она завершается ошибкой при несовместимом изменении. `pnpm test` выполняет ту же проверку автоматически.

Локальный сервер загружает схемы при старте и применяет их до бизнес-логики на границах MobileOps, ERP и MES. Неизвестные поля запрещены в командах и конвертах, идентификаторы и массивы ограничены, а внешние `$ref` не загружаются из сети. Общий JSON-парсер также ограничивает размер, глубину и число ключей и отклоняет `__proto__`, `prototype` и `constructor`.

При несовместимом изменении создаётся новая версия схемы и сохраняется поддержка ранее принятых исходных событий. Схему нельзя ослаблять только ради прохождения ошибочного сообщения: преобразование внешнего формата выполняется в адаптере.

## Смешанные заказы ERP

В `workOrder.payload` необязательное поле `item_details` содержит тип и ревизию для каждого `item_id`, если заказ объединяет разную номенклатуру. Для однородных заказов сохраняется прежний формат. При наличии детализации она должна покрывать все изделия ровно один раз и совпадать с каталогом; поля уровня заказа соответствуют первой позиции и не переопределяют остальные. Неизвестные ID, повторные позиции и несовпадающие ревизии отклоняются.
