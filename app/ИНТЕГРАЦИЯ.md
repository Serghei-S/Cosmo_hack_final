# Обмен с производственными системами

Docker API использует [адаптеры 1С и Галактики](ERP_АДАПТЕРЫ.md), [MES и КОМПАС](MES_КОМПАС_АДАПТЕРЫ.md) и [MobileOps](MOBILEOPS_КОНТУР.md). По умолчанию отдельный HTTPS ERP-эмулятор принимает результаты и выдаёт заказы. Состояние адаптеров хранится в общей PostgreSQL.

1. Администратор запрашивает заказ в центре интеграций. Повтор возвращает прежний заказ.
2. Контролёр фиксирует решение. Сервер атомарно сохраняет исходное событие, аудит и задание outbox.
3. Worker получает внешний заказ и передаёт результат с устойчивым correlation key.
4. Квитанция сохраняется; временный отказ приводит к повтору. Окончательная ошибка видна в очереди администратора.
5. Направление на доработку и подтверждённое списание имеют отдельные статусы `rework_required` и `scrapped`; они не подменяются карантином.

Администратор может повторить доставку сохранённого решения, но не создать новый производственный вердикт через интеграционный API. Для 1С и Галактики расширения `REWORK`/`SCRAP` должны поддерживаться шлюзом предприятия.

Тесты протоколов поднимают локальные HTTP-шлюзы. Рабочий Docker-контур использует HTTPS и проверяет CA. Настоящие экземпляры ERP/MES/САПР и робот не заявляются подключёнными без их адресов, конфигурации и испытания на площадке.
