# Сервер ОРБИТА.QC

`app.mjs` — единственная точка входа рабочего Docker API. Модули в родительском каталоге содержат повторно используемые адаптеры и совместимые регрессионные реализации; файловый сервер старого переносимого запуска не используется контейнером.

## Вход при демонстрации

По согласованному режиму демонстрации `compose.yaml` задаёт **`DEMO_MODE=true`**. Парольный вход реализован, но не является обязательным: интерфейс получает сеанс выбранной роли через `/api/security/demo-session`. Переключение ролей доступно без ввода пароля. Эта особенность документируется в бэкенде; дополнительная плашка об отключённом входе на фронтенд не добавлялась.

Демонстрационный режим не удостоверяет личность человека. Он позволяет любому посетителю выбрать в том числе администратора; поэтому публикация стенда за пределы доверенного демонстрационного окружения требует изменения режима. Ролевые ограничения команд, CSRF, область линий и аудит действуют и здесь, но автором записи является выбранная демонстрационная учётная запись.

Для парольного режима:

```sh
docker compose -f compose.yaml -f compose.production.yaml up -d --no-build --scale api=2
```

При `DEMO_MODE=false` endpoint выбора роли возвращает 404. Пользователи импортируются однократно из секрета `users.json`; пароль хранится в БД как scrypt-хеш. Первичные пароли не выводятся в логи. Форма входа остаётся доступной, а роль берётся из серверной учётной записи. При переключении режима демонстрационные и ранее созданные немаркированные сеансы автоматически перестают проходить проверку. Пользователь должен пройти парольный вход.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `db.mjs` | Ограниченные TLS-пулы, транзакции на одном соединении, advisory locks |
| `repository.mjs` | Зашифрованные документы, приём оригиналов, квитанции, неизменяемая история, контроль цепочек |
| `auth.mjs` | Пароли, сеансы, ограничения частоты, CSRF и RBAC |
| `workflow.mjs` | Авторитетные команды; переход проверяется по истории БД, события создаются сервером |
| `media.mjs` | Независимая БД изображений, валидация содержимого, шифрование, SHA-256 |
| `adapters.mjs` | Транзакционный порт хранения для ERP/MES/CAD/MobileOps |
| `worker.mjs` | Outbox, lease, fencing по ID аренды, повторы и подтверждения |
| `executive.mjs` | Серверные визы и подпись руководителя |
| `crypto.mjs`, `hybrid-crypto.mjs` | Шифрование оперативных записей и отдельный гибридный архивный профиль |
| `initialize.mjs`, `restore.mjs` | Первый импорт и восстановление в пустые БД |

## Политика ролей

Источник политики — `app/contracts/workflow-policy.json`. `pnpm contracts:generate` создаёт серверную карту разрешений и TypeScript-контракт; `pnpm contracts:check` обнаруживает дрейф. Технологу доступны гипотеза, подробный разбор причины и запрос сведений. Команды `tech_allow` и `tech_deny` исключены. Тип исторического события `technical_disposition` читается для совместимости сохранённых исходных наборов и не наделяет технолога производственными полномочиями.

Контролёр принимает окончательные решения о выпуске и списании. Мастер фиксирует выполнение либо предложение о списании, затем контролёр подтверждает результат. Неизвестное действие, неподходящая роль, недоступная линия и неверная ревизия отклоняются до записи производственных событий.

## Основные API

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/config` | Публичные параметры запуска без секретов |
| `POST /api/security/login`, `/demo-session`, `/logout` | Управление сеансом |
| `GET /api/data/bootstrap` | Данные разрешённых линий и пользовательские настройки |
| `GET /api/security/events?cursor=…` | Обновление истории; при том же курсоре — `unchanged` |
| `POST /api/workflow/commands` | Идемпотентная команда с `expectedRevision` и основанием |
| `POST /api/events/ingest` | Пакет до 200 внешних событий; человеческие решения запрещены |
| `GET /api/events/receipts` | Итоги приёма и последние ошибки для администратора |
| `POST /api/media`, `GET /media/:filename` | Загрузка и защищённая выдача фото |
| `GET/POST /api/preferences/:key` | Черновики, чек-листы и пользовательские справочники с ревизией |
| `GET/POST /api/executive/approvals` | Визы руководителя |
| `GET /api/security/verify`, `/audit`, `/sessions` | Контроль журнала и сеансов |
| `POST /api/security/sessions/revoke` | Отзыв сеанса |
| `GET/POST /api/operations/backups` | Последняя копия / новый снимок |
| `GET/POST /api/operations/outbox` | Очередь и ручной повтор после ошибки |
| `/api/integrations/*`, `/api/plant/*`, `/api/mobile/*` | Протокольные адаптеры |
| `GET /health/live`, `/health/ready`, `/metrics` | Внутренняя диагностика; метрики закрыты на внешнем Nginx |

## Эксплуатационные ограничения

Текущий источник номенклатуры и доменной конфигурации — подготовленный набор при инициализации. При вводе новой площадки нужны проверенная загрузка её каталогов, замена демонстрационных сценарных правил и контрольная миграция. В `domain.ts` сохранены правила учебных историй ITEM-013…016, включая условный ручной размер: они не должны трактоваться как универсальные производственные нормы.

Месячная управленческая сводка остаётся отдельным синтетическим набором. Общий Compose не включает промышленную PKI, SSO, HA-кластер PostgreSQL или сертифицированную КЭП. Такие системы не подменяются локальной имитацией. Подключение и приёмка описаны в корневом README и `docs/operations.md`.
