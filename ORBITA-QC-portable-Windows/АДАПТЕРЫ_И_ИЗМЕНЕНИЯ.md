# Адаптеры и изменения интеграции ОРБИТА.QC

Этот файл сводит в одном месте изменения для ERP, MES и КОМПАС-3D. Подробные форматы, переменные окружения и примеры приведены в [ERP_АДАПТЕРЫ.md](ERP_АДАПТЕРЫ.md), [MES_КОМПАС_АДАПТЕРЫ.md](MES_КОМПАС_АДАПТЕРЫ.md) и [ИНТЕГРАЦИЯ.md](ИНТЕГРАЦИЯ.md).

| Контур | Что реализовано | Что требуется для реальной системы |
| --- | --- | --- |
| ERP-эмулятор | HTTP-получение заказа, отправка результата контроля, журнал, квитанции и повторные попытки | Ничего: работает с синтетическими данными в переносимом демо |
| 1С | Отдельный профиль: преобразование заказа и результата, сопоставление ID, Basic/Bearer-доступ, постоянный журнал и идемпотентная отправка | Опубликовать согласованный HTTP-сервис в конкретной конфигурации 1С, задать реальные соответствия ID, проверить на тестовой базе |
| «Галактика:ERP» | Отдельный альтернативный ERP-профиль с теми же гарантиями доставки и собственным форматом шлюза | Реализовать согласованный шлюз к установленной «Галактике» и проверить на тестовой базе |
| MES | Получение фактов операций по курсору, сопоставление ID, защита от дублей, автоматическое добавление в хронологию, отправка решений ОТК с квитанциями и повторами | Предоставить шлюз `GET /events` и `POST /quality-status`, реальные справочники и испытать сценарии на MES |
| КОМПАС-3D | Запрос структуры сборки у локального адаптера, проверка дерева и ревизии, запись состава без геометрии; резервный импорт JSON | Написать и испытать процесс на рабочей станции с установленным КОМПАС-3D, который читает сборку через SDK и отдаёт согласованный JSON |

Источник производственного заказа выбирается один: эмулятор, 1С **или** «Галактика». MES передаёт факты исполнения, ОРБИТА.QC формирует решение по качеству, КОМПАС-3D передаёт состав сборки. Внешние ID переводятся через явные словари; неизвестные значения отклоняются. Исходящие сообщения имеют стабильные ключи, поэтому повтор запроса не должен повторно проводить решение у принимающей системы.

## Изменения в проекте

- `erp-adapters.mjs`, `integration.mjs`, `plant-integrations.mjs`: серверные профили и маршруты `/api/integrations/*`, `/api/plant/*`.
- `source/src/admin-integrations.tsx`, `source/src/plant-sync.ts`, `source/src/App.tsx`, навигация и стили: страницы обмена и автоматическая синхронизация MES, пока открыт сайт.
- `source/integration-fixtures/`: примеры сопоставлений и сообщений для ERP, MES и КОМПАС-3D.
- `quality_dataset/contracts/integration-*.schema.json`: расширение нормализованных контрактов для ERP-профилей.
- `source/tests/*integration*.test.mjs`, `source/tests/erp-adapters.test.mjs`: проверки обмена на локальных HTTP-стендах.
- `server.mjs`, `source/scripts/package-windows.py`, `README.md` и профильная документация: включение маршрутов, упаковка и описание границ.

## Текущий статус и ограничения

Адаптеры проверены на локальных имитаторах HTTP-шлюзов, а не на установленных 1С, «Галактике», MES или КОМПАС-3D. Процесс чтения КОМПАС через SDK в репозитории пока отсутствует. Критические действия ролей проходят серверную авторизацию и защищённый аудит; `localStorage` остаётся учебной проекцией. Для нескольких рабочих мест нужна общая база. В текущем демо автоматическая передача решений в MES требует открытой страницы. Зашифрованное состояние серверного обмена хранится в исключённой из Git папке `data/`.

Проверка после изменения кода: `cd source; pnpm test; pnpm build`. Переносимая сборка: `node scripts/portable.mjs`, затем `py -3 scripts/package-windows.py`.
