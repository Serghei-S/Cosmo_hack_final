# ОРБИТА.QC — исходный код

React 19, TypeScript strict, Vite 6. Новых production-зависимостей нет.

## Запуск и пересборка

```powershell
pnpm install --frozen-lockfile
pnpm data:sync
pnpm dev
pnpm contracts:check
pnpm test
pnpm security:scan
pnpm build:portable
pnpm sbom:generate
pnpm ci:check
```

`data:sync` читает `../../quality_dataset/expanded_dataset`: 180 изделий, справочники, индекс 18 фото и **только** `events/source_deliveries.jsonl`. Основной набор остаётся в соседней папке `quality_dataset`. Скрипт собирает `src/demo-data.json`, реальные изображения в `public/media/` и копии внешнего и ошибочного потоков в `public/demo/`. Три исторических решения ОТК и синтетический контекст технолога формируются отдельно скриптом `scripts/technologist-fixtures.mjs` и помечены источником/ревизией; оригиналы основного набора не переписываются. Хеши встроенных сообщений находятся в `src/integrity-manifest.json`. План контроля и проектные интеграционные профили хранятся отдельно в `src/config.json`. Старый набор из 12 изделий не импортируется повторно. Файлы `expected/*` и `interactions/scripted_actions.jsonl` не являются входом приложения.

Заключения и запросы технолога, а также сведения мастера записываются через серверное согласование в защищённый журнал `../data/security/audit.jsonl`; браузерное хранилище содержит его проекцию и черновики. Чек-лист и незавершённый текст заключения остаются локальными для текущего браузера. Ответы ОГМ и ЦЗЛ пока представлены демонстрационными исходными событиями: автоматического обмена с этими службами нет. Рабочий сценарий описан в `docs/technologist-workflow.md`.

`pnpm build:portable` выполняет строгую проверку типов, Vite-сборку и переносит `dist/` в `../site/`. Для обновления итогового архива из этой папки запустите `py -3 scripts/package-windows.py`: скрипт создаст `../../ORBITA-QC-workspaces-Windows.zip` с переносимым приложением и расширенным набором данных. Для запуска готовой версии используйте `../START.cmd`. При разработке сначала запустите API в другом терминале: `$env:ORBITA_PORT=5174; node ../server.mjs`, затем `pnpm dev`; Vite перенаправляет `/api` на порт 5174. Один `pnpm dev` без API покажет ошибку соединения.

`pnpm ci:check` проверяет контракты, тесты, наличие runtime-секретов в Git, production-сборку и CycloneDX SBOM. В локальном демо роль выбирается без входа; это не удостоверение личности. Сервер создаёт отдельный сеанс для выбранной роли, чтобы проверять права и фиксировать действия в аудите. Ротация ключа выполняется при остановленном сервере командой `pnpm security:rotate -- --confirm`.

## Работа демо

- При первом открытии приложение принимает внешний поток до первого сигнала или невозможности оценки для каждого проблемного изделия. Обычные изделия проходят автоматически. Последующие внешние операции этих изделий остаются в ожидании действия роли.
- Администратор → «Поток событий» → «Сценарии и воспроизведение» управляет загрузкой встроенного набора, паузой, следующим шагом, продолжением, сбросом и импортом JSON/JSONL. «Качество данных» отдельно показывает результаты приёма. «Проверить ошибочный поток» берёт из `ingest_stream.jsonl` только намеренно ошибочные доставки.
- Контролёр работает в трёхколоночном кокпите: очередь, исходные кадры и досье с закреплённым пультом решения. Доступны фильтры, сравнение кадров, проверка SHA-256 файлов, клавиши F1–F4, пробел и Z. Если фото, замера, документа или реквизита нет в источнике, соответствующее поле остаётся пустым; решение по непригодному кадру блокируется. Мастер фиксирует работу с исполнителем и комментарием; в опорных сценариях соответствующее учебное фото прикрепляется автоматически. Технолог записывает гипотезу или заключение о допустимости. После работы мастера выпуск оформляет контролёр.
- Сервер разрешает действия по роли и линии, фиксирует автора из сеанса и сохраняет результат в защищённом аудите. `localStorage` хранит учебную проекцию; неподтверждённые локальные действия удаляются при входе. Стартовые заявки мастера обозначены отдельными синтетическими событиями `ORBITA-DEMO`.
- Фото представлены синтетическими учебными материалами. Фото ITEM-013 не заменяет ручной замер: значение, прибор и подтверждение поверки контролёр вводит при решении о выпуске. У ITEM-015 до действия мастера кадр отсутствует. Серверный аудит использует HMAC-цепочку; ERP/MES работают через локальные эмуляторы и HTTP-стенды.

## Границы реализации

Это локальная демонстрация. Серверный обмен работает с локальным ERP-эмулятором; адаптеры ERP, MES и серверный клиент CAD-адаптера проверены только на HTTP-стендах. Настройки и форматы приведены в `../ERP_АДАПТЕРЫ.md` и `../MES_КОМПАС_АДАПТЕРЫ.md`. Входящие JSON-запросы имеют ограничения размера, глубины и числа ключей; неизвестные поля и опасные ключи прототипа отклоняются до бизнес-логики, а доменные сообщения проверяются по схемам из `../contracts/`. Критические действия проверяются сервером и сохраняются в защищённом журнале; браузерное состояние остаётся учебной проекцией. Учебные пароли, локальный ключ и файловый журнал не заменяют корпоративное управление учётными записями, ключами и WORM-хранилище. Полное описание и демонстрация — в `../БЕЗОПАСНОСТЬ_И_АУДИТ.md`. Подключения к настоящим ERP/MES и SDK-процесс КОМПАС-3D не проверены.
