# Серверный обмен ОРБИТА.QC

## Реализованный контур

`server.mjs` обслуживает сайт и JSON API на `127.0.0.1:5173` (либо следующем свободном порту). ERP-эмулятор опубликован в том же локальном HTTP-сервере отдельными маршрутами. Сервер ОРБИТА.QC действительно отправляет ему HTTP-запросы, обрабатывает ответ и сохраняет зашифрованное состояние в `data/integration-state.json`. При следующем запуске журнал восстанавливается. Файл состояния исключён из Git и итогового архива.

| Маршрут | Метод | Назначение |
| --- | --- | --- |
| `/api/integrations/state` | GET | Полученные заказы, исходящие сообщения, квитанции, сборки |
| `/api/integrations/pull` | POST | Запросить заказ у активного профиля ERP по внутреннему `work_order_id` |
| `/api/integrations/results` | POST | Отправить результат по `item_id`, `quality_status`, `basis_event_ids` |
| `/api/integrations/retry/{correlation_key}` | POST | Повторить не подтверждённое сообщение |
| `/api/integrations/cad` | POST | Импортировать условную JSON-структуру сборки |
| `/api/plant/state` | GET | Состояние шлюзов MES и КОМПАС-3D, журналы и ошибки |
| `/api/plant/mes/configured` | GET | Признак настройки MES для рабочих мест без доступа к админскому журналу |
| `/api/plant/mes/sync` | POST | Получить следующий пакет фактов MES по курсору |
| `/api/plant/mes/decisions` | POST | Поставить решение ОТК в очередь MES по `event_id` |
| `/api/plant/mes/retry/{event_id}` | POST | Повторить отправку решения |
| `/api/plant/cad/pull` | POST | Получить структуру сборки у локального CAD-адаптера |
| `/api/emulator/orders/{work_order_id}` | GET | Источник заданий, доступен только в профиле эмулятора |
| `/api/emulator/results` | POST | Приём результата и квитанция, только профиль эмулятора |

Форматы сообщений соответствуют `quality_dataset/contracts/integration-*.schema.json`. Исходные воспроизводимые примеры скопированы в `source/integration-fixtures/`. Другие заказы формируются детерминированно из `source/src/demo-data.json`.

## Сценарий демонстрации

1. В рабочем месте администратора откройте «Центр интеграций» → «Журнал обмена».
2. Получите заказ `WO-B`. Повторный запрос вернёт `duplicate` и не создаст второй заказ.
3. Выберите учебный результат `ITEM-007` и отправьте. На первой попытке эмулятор вернёт `temporary_unavailable` с кодом ошибки.
4. Через три секунды сервер повторит отправку. В журнале появится квитанция `accepted` и две попытки. Можно также нажать «Повторить» вручную.
5. На вкладке «КОМПАС и сборки» импортируйте условную сборку. Повторный импорт той же ревизии не создаст дубликат; конфликт состава той же ревизии вернёт HTTP 409.

Корреляционный ключ результата вычисляется из содержимого сообщения. Повтор одной и той же отправки не создаёт вторую запись. Запись результата без предварительно полученного заказа возвращает HTTP 409. Неизвестный заказ и ошибочный JSON отклоняются. После пяти неудачных попыток сообщение остаётся в состоянии `failed` для ручного разбора и повтора.

## Границы и переход к системам предприятия

Локальный эмулятор остаётся профилем по умолчанию. Теперь сервер также содержит адаптеры 1С и «Галактика:ERP», которые преобразуют данные и квитанции согласованных HTTP/JSON-шлюзов. Они проверены на локальных стендах, но не подключены к установленным продуктам. Контракты шлюзов, настройки, сопоставление ID и границы проверки описаны в `ERP_АДАПТЕРЫ.md`. Одну ERP назначают источником задания; профили 1С и «Галактики» альтернативны.

MES и КОМПАС-3D имеют отдельные серверные контуры, описанные в `MES_КОМПАС_АДАПТЕРЫ.md`. Для MES реализованы курсор, сопоставление фактов операций, автоматическая передача решений из открытого сайта, квитанции и повторы. Для КОМПАС-3D реализован прямой запрос к локальному адаптеру, проверка дерева и ревизии; резервный JSON-импорт сохраняется. SDK-процесс на рабочей станции с установленным КОМПАС-3D ещё нужно создать и испытать. Геометрия не заявляется импортированной.

Сервер слушает только `127.0.0.1`. Вход под учебной учётной записью, серверная проверка роли и CSRF защищают маршруты обмена; критические действия сохраняются в зашифрованном аудите. `localStorage` остаётся кэшем сценария. Для промышленного контура нужны общая транзакционная база решений, корпоративные учётные записи и ключи, TLS, независимая копия аудита и резервное копирование. Подробности — в `БЕЗОПАСНОСТЬ_И_АУДИТ.md`.
