# Публичный демонстрационный стенд

[Открыть ОРБИТА.QC](https://orbita-193-233-220-37.sslip.io/).

## Размещение

Ubuntu 24.04, 1 vCPU, 2 ГБ RAM. Каталог приложения — `/opt/orbita`. Docker Compose запускает один API, веб-интерфейс, ERP-эмулятор и две отдельные PostgreSQL. Снаружи доступны HTTP с перенаправлением и HTTPS; порт веб-контейнера привязан к `127.0.0.1:8443`, порты БД не опубликованы.

Внешний Nginx завершает TLS с сертификатом Let's Encrypt и передаёт запросы веб-контейнеру по HTTPS с проверкой локального CA. Действует таймер автоматического продления сертификата. Домен sslip.io указывает на адрес VPS; для постоянной эксплуатации следует закрепить собственный домен.

Ограничения контейнеров: API — 768 МиБ, ERP-эмулятор — 256 МиБ, каждая БД — 256 МиБ, веб — 96 МиБ. Пул API ограничен шестью соединениями, эмулятора — тремя. Добавлен swap 2 ГБ для кратковременных пиков; он не заменяет оперативную память. Эта конфигурация предназначена для демонстрации, а не для подтверждения промышленного SLA.

## Данные и режим демонстрации

Первый запуск импортировал 180 изделий, 2157 событий и 18 фотографий. Последующие действия пользователей добавляются к этой истории. Данные размещены в `.runtime/postgres` и `.runtime/media-postgres`; резервные копии — в `.runtime/backups`. Обновление контейнеров не переинициализирует БД.

Вход сохранён в коде, но на стенде включён `DEMO_MODE=true`: рабочие места переключаются без пароля. Это сознательная настройка демонстрационного бэкенда; такой режим нельзя использовать с реальными производственными данными. Настройка обязательного входа описана в [документации сервера](../app/source/server/README.md).

ERP-эмулятор подключён отдельным сервисом. Внешние MES, 1С, Галактика, КОМПАС и реальные мобильные устройства требуют шлюзов предприятия. Секреты созданы отдельно на VPS, находятся в `.secrets` и не публикуются в Git.

## Обслуживание

На текущем сервере ресурсные ограничения и публичный Origin заданы в локальном `compose.stand.local.yaml`:

```sh
cd /opt/orbita
docker compose -f compose.yaml -f compose.stand.local.yaml ps
docker compose -f compose.yaml -f compose.stand.local.yaml logs --tail 100 api
docker compose -f compose.yaml -f compose.stand.local.yaml up -d --no-build --scale api=1 --wait
sudo nginx -t
systemctl status certbot.timer
```

Сборка из исходников воспроизводится корневым `Dockerfile`. Исправление смешанных ERP-заказов установлено поверх исходного образа отдельным слоем `orbita-qc-api:stand-20260927`; API и эмулятор используют один обновлённый образ. При следующем выпуске собирается новый образ из актуальной главной ветки и обновляется его ссылка в локальном Compose.

Проверка состояния контейнеров и HMAC-цепочек не заменяет проверку восстановления. Порядок резервирования, переноса ключей и восстановления — в [эксплуатационной документации](operations.md).
